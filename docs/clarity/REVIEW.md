# Clarity review — public artifacts and vocabulary

Method: `unslop/v1` for expression, `clarity/v1` for persisted artifacts. Each reviewed artifact has a receipt in `receipts.json` recording its digest, the governing sources that give it meaning, and whether text changed. `python scripts/clarity_status.py` recomputes the state of every receipt (`CURRENT`, `TEXT_STALE`, `BASIS_STALE`, `EXEMPT`) and prints coverage. It is not part of `scripts/qa.py`; adding it there would make every doc edit require a re-review, which is a policy choice for the maintainer.

## Population

Eligible: every reader-facing prose artifact in the repository and the deployed site: root `*.md` guidance, `docs/`, `skills/`, `reference/`, `examples/README.md`, the schema descriptions in `formats/`, and the in-app copy in `index.source.html`.

Exempt: `index.html` (generated by `build.py`), `mcp/tools.json` (machine manifest), and the historical acceptance records the README already marks as records rather than living documentation: `BETA-0.1.md`, `QA-0.1.md`, `RC-0.1.md`, `RC-FINISH-LINE.md`, `PUBLIC-BETA-FREEZE.md`, `MODULE-QA.md`, `contrast-audit.md`, `ATTACHMENT-CONCERN-AUDIT.md`. Their older wording stays as history.

## Decisions that shaped the rewrite

1. **One name for the 0D primitive.** Human-facing prose says **Port**. *Attachment point* is reserved for the implementation concern (`src/06-attachment-core.js`) and the machine records (`parts.points`, `aAttachment`, `config.attachmentPoints`). Before this pass the README, the in-app copy, and the model docs alternated between the two, and the editor used three labels for the same thing ("Attachment settings", "PORT PART", "+ Port part").
2. **"Connection" is not a Wire.** In the model, a connection is a Port's slot record (`connections[]`, carrying `flow` and `access`). The in-app help and two accessibility labels still used "Connection" to mean Wire; they now say Wire. Element ids such as `barConnectionLabel` are machine names and are untouched.
3. **One owner per definition.** The direction/access/authority paragraph was pasted verbatim into seven files. `DATA-FORMATS.md` now owns the field-level definition, `reference/REFERENCE.md` owns the conceptual one, `GLOSSARY.md` maps terms to machine values, and the other files point there or state the rule in one sentence.
4. **Docs match code, not the other way round.** `FORM-MODEL.md` listed `dimension: 3`; the normalizer clamps to 2 (`src/10-model.js`). `MCP.md` listed seven tools; `mcp/tools.json` serves twelve. Both docs now state what the build does.
5. **Archaeology removed from current readers.** "The editor now distinguishes…", "is restored to the distributable package", "There is no persistent Canvas mode or context badge in the toolbar", and the `Beta.10` title on the Form model described past transitions, not the current contract.
6. **Deliberate voice kept.** The vision documents, `HOST-SURFACE-MODEL.md`, `PERFORMANCE.md`, `FILE-MODEL.md`, `LOCAL-SETUP.md`, and `docs/BRANCHING.md` were reviewed and left unchanged; their density is earned and their claims match their sources.

## Residuals

Semantic questions this pass did not resolve. Each needs a maintainer decision, not a rewrite.

- **Product name.** `SOV Schematic` (UI header, API object, schemas, skills, README) versus `Schematically` (repository name, `docs/vision/DATA-DRIVEN-SCHEMATIC-LANGUAGE.md`). The glossary records `SOV Schematic` as the product and `schematically` as the repository. The vision document's "Schematically should become…" was left alone in case it names the intended future product.
- **"Modifier qualifies."** The in-app Reading help listed a fourth noun, Modifier, that nothing in the source, docs, or git history defines. It was removed. If it named something real (editor states? template traits?), restore it with a definition in `GLOSSARY.md`.
- **Template names collide with model terms.** The palette has templates whose ids are `port` and `path`; the model has Port, and the post-RC grammar has Path. Not renamed: template ids are machine data and product design.
- **Mark has two meanings.** In 0.1 it is the glyph legend in the palette help; in `docs/vision/TOPOLOGY-CELL-GRAMMAR.md` it is a modeled entity. The glossary records both; the collision lasts until the vision lands or the legend is renamed.
- **Surface has three senses.** The model surface (`canvasId`), a Port's exposed surface, and the agent surface (browser API / HTTP / MCP). The glossary separates the first from the third and prose now says "entry point" for the third where the two could be confused. The machine name for the first remains `canvas`.
- **`dimension: 3`.** If 3 is meant to be accepted as authored data ahead of Space, that is a code change in `src/10-model.js`, and `FORM-MODEL.md` should change with it.
- **`soveraeign` spelling** in the schema namespace is machine text and untouched.

## Re-running

```bash
python scripts/clarity_status.py            # state of every receipt + coverage
python scripts/clarity_status.py --update   # after a deliberate re-review: refresh digests
```

A changed governing source flips its readers to `BASIS_STALE`; that is the signal to re-read the reader against the source, then `--update`.
