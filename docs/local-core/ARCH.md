# Architecture evidence

Run `node scripts/arch_scan.mjs --out <evidence-directory>` through the native work contract after environment admission. Dependencies are development tools only; none enter the desktop runtime. Root prepares the npm lock and installs pinned dependencies after admission.

The declared scope is every immediate `src/*.js` and `mcp/*.mjs` file. The scanner rejects scope/file byte ceilings and stops its worker after 180 seconds. It writes JSON, Mermaid and DOT artifacts only to the supplied evidence directory. It never fixes production code or regenerates the product. Generated `index.html` is excluded from source counts and duplication signals, but its freshness is checked against the same template/script/CSS/pack composition as `build.py`.

ESLint checks correctness without formatting rules or automatic fixes. Inline disabling comments cannot suppress findings. Espree and eslint-scope map classic browser declarations/references using the script order in `index.source.html`. Those inferred shared-global edges are separate from dependency-cruiser's extracted imports. Recognized UMD root/globalThis properties add labelled inferred edges. Dynamic property access, arbitrary aliases and runtime call paths remain outside this static proof. A reference to an owner loaded later is recorded; it does not imply failure because function calls may happen after startup.

`MODULES.md` owns module concerns. `arch.config.json` declares its DOM-free cores, environment adapters and MCP storage import boundaries. The state-surface pack loader is an environment adapter: it loads browser packs from the bundled tag and receives Node packs from the server. Three exact existing delegation edges are declared; other core/editor edges fail. HTML element IDs that browsers expose through named access have their actual template owner recorded, with a warning for each implicit read. This coupling remains visible for independent review. Duplicate lexical owners, parse failures, unresolved imports/globals, stale build and ownership violations fail the scan. All other ESLint errors fail too; warnings remain available for review.

Cycle sets, branch complexity, code-line counts and repeated substantial lines are review signals rather than universal architecture grades. Function complexity excludes nested function bodies. Line counts are not executable test coverage. Agent qualification must inspect the actual graph, declared module responsibilities, error findings, lifecycle and MCP behavior; a zero exit code alone cannot establish product stability.

`architecture.json` retains source/build input hashes, tool versions, policy, elapsed time, file counts, findings and both graphs. `dependency-cruiser.json` retains the original import extraction. Solid diagram edges mean extracted imports; dashed edges mean inferred shared globals. Checks are invalid when any recorded source, config, tool, lock or build input identity changes.

Tool references: [ESLint language/runtime configuration](https://eslint.org/docs/latest/use/configure/language-options), [dependency-cruiser](https://github.com/sverweij/dependency-cruiser), and its [programmatic API](https://github.com/sverweij/dependency-cruiser/blob/main/doc/api.md). Versions were pinned from official npm registry metadata on 2026-10-11.
